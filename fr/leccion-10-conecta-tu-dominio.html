LEÇON 10 · DOMAINE ET DNS

Connectez votre propre domaine.

Votre site possède une structure, un design et plusieurs pages. Vous allez maintenant apprendre ce qu’est un domaine et comment utiliser une adresse professionnelle pour accéder à votre projet.

Niveau · Débutant Durée · 25–35 min Parcours · Création web

01

Qu’est-ce qu’un domaine ?

Un domaine est le nom que l’on saisit dans le navigateur pour accéder à un site web.

Par exemple :

www.miproyecto.com

Au lieu de retenir une adresse technique, nous utilisons un nom facile à reconnaître.

Le domaine est l’adresse de votre site, mais ce n’est pas le site lui-même.

02

Le domaine et l’hébergement sont deux choses différentes.

Il est important de distinguer ces deux concepts.

01

Domaine : c’est l’adresse utilisée pour trouver un site.

02

Hébergement : c’est le service où sont stockés et servis les fichiers du site.

Dans un projet hébergé avec GitHub Pages, GitHub peut servir les fichiers de notre site.

03

Que sont les DNS ?

DNS signifie Domain Name System.

Pour simplifier, les enregistrements DNS indiquent vers quel service un domaine doit être dirigé.

Nous pouvons imaginer ce processus :

miproyecto.com
↓
DNS
↓
serveur ou service où le site est publié
Pour connecter un domaine, vous devrez généralement modifier certains enregistrements DNS auprès du fournisseur qui gère ce domaine.

04

Le domaine principal et www.

Ces deux adresses sont liées, mais peuvent techniquement être configurées avec des enregistrements différents :

miproyecto.com
www.miproyecto.com

La première est généralement appelée domaine racine ou domaine apex.

www est un sous-domaine.

05

Configurez le domaine dans GitHub Pages.

Si votre projet est publié avec GitHub Pages, le domaine personnalisé se configure depuis le dépôt correspondant.

01

Ouvrez le dépôt de votre projet.

02

Allez dans Settings.

03

Ouvrez la section Pages.

04

Recherchez Custom domain.

05

Saisissez le domaine à utiliser.

GitHub vérifiera ensuite si la configuration DNS du domaine est correcte.

06

Configurez les enregistrements DNS.

L’étape suivante se déroule chez le fournisseur qui gère votre domaine.

Les enregistrements nécessaires peuvent varier selon que vous utilisez le domaine racine ou un sous-domaine comme `www`.

Ne copiez pas les adresses IP ou les valeurs DNS d’un ancien tutoriel. Consultez toujours la documentation actuelle du service où vous publiez le site.

07

Qu’est-ce qu’un enregistrement CNAME ?

Un enregistrement CNAME permet à un nom, comme un sous-domaine, de pointer vers un autre nom de domaine.

Par exemple, dans une configuration GitHub Pages, vous pourriez devoir associer :

www

à une adresse comme :

usuario.github.io

La valeur exacte dépendra de votre compte et de la configuration du projet.

08

Les modifications DNS peuvent prendre du temps.

Après une modification, le changement peut ne pas être visible immédiatement partout.

Ce processus est généralement appelé propagation DNS.

Si vous venez d’effectuer correctement une modification DNS et qu’elle ne fonctionne pas encore, ne modifiez pas les enregistrements sans arrêt. Vérifiez d’abord la configuration et laissez le changement se propager.

09

Activez HTTPS.

HTTPS permet de chiffrer la connexion entre le navigateur et la page.

Lorsque GitHub Pages a vérifié le domaine, cherchez dans les paramètres de Pages l’option relative à HTTPS.

L’adresse devrait utiliser :

https://miproyecto.com

au lieu de :

http://miproyecto.com

10

Vérifiez les différentes versions.

Une fois la configuration terminée, vérifiez les adresses correspondant à votre configuration.

https://miproyecto.com
https://www.miproyecto.com

L’objectif est que le visiteur accède correctement à la version principale que vous avez configurée.

11

Erreurs fréquentes.

01

Mal écrire le domaine.

02

Configurer un mauvais enregistrement DNS.

03

Conserver des enregistrements incompatibles ou en double.

04

Ne pas attendre la propagation des changements DNS.

05

Oublier de vérifier HTTPS.

12

Ne modifiez pas les enregistrements sans comprendre leur rôle.

Le panneau DNS peut contenir des enregistrements utilisés par d’autres services.

Certains enregistrements peuvent, par exemple, être liés à l’adresse e-mail de votre domaine.

Avant de supprimer un enregistrement existant, cherchez à quoi il sert. Connecter un site ne signifie pas qu’il faut supprimer tous les enregistrements DNS existants.

RÉSUMÉ

Ce que vous avez appris.

  • Ce qu’est un domaine.
  • La différence entre domaine et hébergement.
  • Le rôle du système DNS.
  • La différence entre le domaine racine et www.
  • Où configurer un domaine dans GitHub Pages.
  • Le rôle possible d’un enregistrement CNAME.
  • Pourquoi les changements DNS peuvent prendre du temps.
  • L’importance d’utiliser HTTPS.
  • Pourquoi vérifier différentes versions du domaine.
  • Pourquoi ne pas supprimer des enregistrements DNS sans les examiner.

MISE EN PRATIQUE

Préparez la connexion de votre domaine.

Même si vous ne souhaitez pas encore acheter ou connecter un domaine, assurez-vous de comprendre le processus.

  1. Identifiez où votre site est publié.
  2. Identifiez où vous géreriez votre domaine.
  3. Repérez la section DNS du fournisseur.
  4. Repérez Settings → Pages dans GitHub.
  5. Identifiez le champ Custom domain.
  6. Consultez la documentation actuelle de GitHub Pages.
  7. Vérifiez comment HTTPS serait configuré.
Vous n’avez pas besoin d’acheter un domaine pour terminer ce parcours. L’essentiel est de comprendre comment le connecter lorsque vous souhaiterez en utiliser un.
