LECCIÓN 10 · DOMINIO Y DNS

Conecta tu propio dominio.

Tu web ya tiene estructura, diseño y diferentes páginas. Ahora aprenderás qué es un dominio y cómo puedes utilizar una dirección profesional para acceder a tu proyecto.

Nivel · Principiante Tiempo · 25–35 min Ruta · Diseño web

01

¿Qué es un dominio?

Un dominio es el nombre que las personas escriben en el navegador para acceder a una página web.

Por ejemplo:

www.miproyecto.com

En lugar de recordar una dirección técnica, utilizamos un nombre fácil de reconocer.

El dominio es la dirección de tu web, pero no es la web en sí misma.

02

Dominio y hosting no son lo mismo.

Es importante distinguir estos dos conceptos.

01

Dominio: es la dirección que utilizamos para encontrar una web.

02

Hosting: es el servicio donde se almacenan y sirven los archivos de la web.

En un proyecto alojado con GitHub Pages, GitHub puede encargarse de servir los archivos de nuestra web.

03

¿Qué son los DNS?

DNS significa Domain Name System.

De forma sencilla, los registros DNS ayudan a indicar hacia qué servicio debe dirigirse un dominio.

Podemos imaginar este proceso:

miproyecto.com
↓
DNS
↓
servidor o servicio donde está publicada la web
Cuando conectas un dominio, normalmente tendrás que modificar algunos registros DNS desde la empresa donde administras ese dominio.

04

El dominio principal y www.

Estas dos direcciones están relacionadas, pero técnicamente pueden configurarse mediante registros diferentes:

miproyecto.com
www.miproyecto.com

La primera se conoce habitualmente como dominio raíz o dominio apex.

www es un subdominio.

05

Configura el dominio en GitHub Pages.

Si tu proyecto está publicado mediante GitHub Pages, la configuración del dominio personalizado se realiza desde el repositorio correspondiente.

01

Abre el repositorio de tu proyecto.

02

Entra en Settings.

03

Abre la sección Pages.

04

Busca Custom domain.

05

Introduce el dominio que quieres utilizar.

GitHub comprobará después si la configuración DNS del dominio es correcta.

06

Configura los registros DNS.

El siguiente paso se realiza desde el proveedor donde administras tu dominio.

Dependiendo de si utilizas el dominio raíz o un subdominio como `www`, los registros necesarios pueden ser diferentes.

No copies direcciones IP o valores DNS de un tutorial antiguo. Consulta siempre la documentación actual del servicio donde estás publicando la web.

07

¿Qué es un registro CNAME?

Un registro CNAME permite que un nombre, como un subdominio, apunte hacia otro nombre de dominio.

Por ejemplo, en una configuración de GitHub Pages podrías necesitar relacionar:

www

con una dirección similar a:

usuario.github.io

El valor exacto dependerá de tu cuenta y de la configuración de tu proyecto.

08

Los cambios DNS pueden tardar.

Después de modificar los registros, es posible que el cambio no sea visible inmediatamente en todos los lugares.

Este proceso suele denominarse propagación DNS.

Si acabas de realizar correctamente un cambio DNS y todavía no funciona, no modifiques continuamente los registros. Primero comprueba la configuración y permite que el cambio se propague.

09

Activa HTTPS.

HTTPS permite que la conexión entre el navegador y la página utilice cifrado.

Cuando GitHub Pages haya verificado correctamente el dominio, revisa en la configuración de Pages la opción relacionada con HTTPS.

La dirección debería utilizar:

https://miproyecto.com

en lugar de:

http://miproyecto.com

10

Comprueba las diferentes versiones.

Cuando termines la configuración, comprueba las direcciones que correspondan a tu configuración.

https://miproyecto.com
https://www.miproyecto.com

El objetivo es que el visitante llegue correctamente a la versión principal que hayas configurado.

11

Errores frecuentes.

01

Escribir incorrectamente el dominio.

02

Configurar un registro DNS equivocado.

03

Mantener registros incompatibles o duplicados.

04

No esperar a que los cambios DNS se propaguen.

05

Olvidar comprobar HTTPS.

12

No cambies registros sin saber qué hacen.

El panel DNS puede contener registros utilizados por otros servicios.

Por ejemplo, algunos registros pueden estar relacionados con el correo electrónico de tu dominio.

Antes de eliminar un registro existente, averigua para qué se utiliza. Conectar una web no significa que debas borrar todos los registros DNS que ya existen.

RESUMEN

Lo que has aprendido.

  • Qué es un dominio.
  • La diferencia entre dominio y hosting.
  • Para qué sirve el sistema DNS.
  • La diferencia entre el dominio raíz y www.
  • Dónde configurar un dominio en GitHub Pages.
  • Qué función puede tener un registro CNAME.
  • Por qué los cambios DNS pueden tardar.
  • La importancia de utilizar HTTPS.
  • Por qué debes comprobar diferentes versiones del dominio.
  • Por qué no debes eliminar registros DNS sin revisarlos.

PONLO EN PRÁCTICA

Prepara la conexión de tu dominio.

Aunque todavía no quieras comprar o conectar un dominio, asegúrate de entender el proceso.

  1. Identifica dónde está publicada tu web.
  2. Identifica dónde administrarías tu dominio.
  3. Localiza la sección DNS del proveedor.
  4. Localiza Settings → Pages en GitHub.
  5. Identifica el campo Custom domain.
  6. Consulta la documentación actual de GitHub Pages.
  7. Comprueba cómo se configuraría HTTPS.
No necesitas comprar un dominio para completar esta ruta. Lo importante es entender cómo se conecta cuando llegue el momento de utilizar uno.
